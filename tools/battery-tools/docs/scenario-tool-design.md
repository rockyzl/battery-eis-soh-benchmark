# Battery Research Agent: scenario and tool design

Reviewed 29 October 2026. This is an implementation and integration study based on primary papers, project-maintained documentation and source repositories. It is not an exhaustive systematic review or validation of every package. The workflow choices and acceptance rules below are our design proposals. Package capabilities are sourced separately. The demo's numerical reference environment remains impedance.py 1.7.1; the current documentation may describe newer versions. Pin and test adapters before adoption.

## The decision to make first

A battery agent should decide which scientific question the measurements can address before choosing an executable tool. Tool names alone are insufficient: each action must specify its required fields, experiment type, test conditions, method assumptions, numerical settings and evidence boundary. If inputs are absent, the next action is to request or inspect them. The existence of a package does not establish that a calculation is applicable to a given cell.

This demo's first research question is concrete: how do the measured EIS spectra of one LCO/graphite cell differ between diagnostic stages, and which changes can the data support? The connected public collection includes whole-cell spectra and paired capacity diagnostics. It does not supply every electrode reference or physical parameter needed to assign a unique degradation mechanism. Diagnostic index is not physical cycle number.

## Scenario map and tool combinations

| Question | Minimum useful evidence | Candidate tool sequence | Interpretation gate |
|---|---|---|---|
| What do these instrument files contain? | Untouched originals, instrument/software versions, units, cell IDs and protocol | Verified cellpy/BEEP/yadg/galvani reader → schema/unit checks → step segmentation → cell/run mapping; battdat for consistent metadata | Compare the adapter against vendor exports. Never silently reinterpret sign, capacity reset or repeated step numbers. |
| What changed in EIS? | f, Re(Z), Im(Z), cell/stage and matched temperature/SOC/rest context | Inventory → residual/KK assessment → limited RC/CPE candidates → repeated-start fit checks → parameter/residual comparison | Separate data consistency from circuit-fit quality; request matching conditions before attributing change to aging. |
| Are overlapping relaxation contributions present? | Suitable validated EIS and frequency/noise context | EIS checks → pyimpspec DRT → regularization/frequency-window sensitivity → competing circuit hypotheses | Stable time-scale features may motivate hypotheses; peaks alone do not uniquely label mechanisms. |
| Where do capacity and efficiency change? | t, I, V, step/cycle IDs, capacity definitions and cutoffs | cellpy/PyProBE/BEEP ingestion → CC/CV/rest segmentation → capacity/efficiency summaries → matched protocol comparison | Distinguish voltage cutoffs, temperature and rate from irreversible degradation. |
| How do differential features evolve? | Suitable constant-current half-cycles, voltage/capacity resolution, current and temperature | Current/reversal checks → cellpy ICA/DVA → voltage-grid/smoothing sensitivity → comparable-cycle peak analysis | Report preprocessing and feature stability. Do not turn a peak shift alone into quantified LLI or LAM. |
| Which electrode degradation modes fit? | Low-rate full-cell/pseudo-OCV curves and matched positive/negative electrode OCP references | ICA/DVA context → PyProBE OCV fitting or PyDMA → multi-start/window/weight checks → independent voltage reconstruction | Missing half-cell references or non-identifiable fits prevent a strong electrode-level claim. |
| Does pulse resistance increase? | Time-resolved voltage/current around actual steps, pulse/rest IDs, SOC and T | Pulse detection → PyProBE pulsing → ΔV/ΔI at explicitly chosen delays → matched-SOC/T comparison | State sampling delay and sign. R at 10 s includes dynamics and is not identical to high-frequency R0 or a full impedance spectrum. |
| What can GITT say about transport? | Galvanostatic pulse and relaxation records, geometry/active-material inputs, applicable model | Segment pulses/rest → inspect polarization and relaxation → choose GITT model/time interval → geometry and window sensitivity | Without justified assumptions, report measured polarization/relaxation and missing inputs rather than an unqualified diffusion coefficient. |
| What can PITT say about transport? | Potential steps and measured current transients, timing and geometry | Identify potential steps → examine background/early transients → appropriate short/long-time model → sensitivity checks | Do not apply a GITT voltage-relaxation formula to PITT current transients; check capacitive and charge-transfer contributions. |
| Can a physical model reproduce voltage? | I/T protocol, V trace, chemistry/cell design parameters and initial state | Select PyBaMM model → PyBOP fitting → sensitivity/alternative parameter sets → withheld-protocol comparison | A default parameter set describes a particular cell. Low error is insufficient to establish identifiability or transfer across chemistries. |
| Does a forecast improve on simple alternatives? | Properly aligned histories, future labels and independent cells | Audit → grouped feature/model selection → future-capacity model → persistence/mean baselines → transfer checks | Splits and feature timing must match the intended use; do not force prediction into a descriptive task. |

The machine-readable bilingual version is [agent-workflows.json](agent-workflows.json). It is rendered inside the conversation's Analysis scenarios control. Each scenario includes primary source links and an explicit live/integration status.

## Tool ecosystem: why each package belongs

- **impedance.py:** preprocessing, KK consistency tests, circuit fitting and visualization. It is suitable for an EIS adapter, not automatic physical attribution. [Documentation](https://impedancepy.readthedocs.io/en/latest/index.html), [validation](https://impedancepy.readthedocs.io/en/latest/validation.html).
- **pyimpspec:** KK and multiple DRT methods. Its documentation recommends spectrum validation before DRT and warns that regularization can create or merge peaks. [DRT guide](https://vyrjana.github.io/pyimpspec/guide_drt.html), [KK guide](https://vyrjana.github.io/pyimpspec/guide_kramers_kronig.html).
- **cellpy:** cycling-data workflows and ICA/DVA with documented smoothing and resolution choices. [ICA example](https://cellpy.readthedocs.io/en/stable/examples/04_incremental_capacity_analysis/).
- **PyProBE:** processing experiments, pulse resistance and OCV/degradation fitting. Its pulse analysis exposes resistance at selected elapsed times. [Pulse example](https://pyprobe.readthedocs.io/en/stable/examples/analysing-GITT-data.html), [OCV fitting](https://pyprobe.readthedocs.io/en/stable/examples/ocv-fitting.html), [project](https://github.com/ImperialCollegeLondon/PyProBE).
- **BEEP:** validation, structuring and featurization of high-throughput cycling data, with prediction examples. This supports a reproducible ingestion-to-model pipeline; it does not make every trained model transferable. [SoftwareX paper](https://doi.org/10.1016/j.softx.2020.100506), [project](https://github.com/TRI-AMDD/beep).
- **PyBaMM + PyBOP:** distinguish battery simulation from parameter estimation. PyBaMM supplies models and parameter sets; PyBOP offers parameter inference/optimization workflows. [Parameters](https://docs.pybamm.org/en/latest/source/examples/notebooks/getting_started/tutorial-4-setting-parameter-values.html), [PyBOP](https://github.com/pybop-team/PyBOP). The current PyBOP source documents a major API restructure, so examples from different versions must not be mixed silently.
- **PyDMA:** reconstructs pseudo-OCV with electrode OCP references and supports OCV/DVA/ICA fitting objectives, including blend-electrode cases. This is a richer evidence requirement than detecting peaks. [Maintainer repository](https://github.com/tum-ees/pydma).
- **battdat, yadg and galvani:** complementary candidates for standardized datasets, protocol/metadata extraction and instrument-specific reading. They are not interchangeable universal parsers. [battdat](https://rovi-org.github.io/battery-data-toolkit/), [yadg](https://dgbowl.github.io/yadg/main/parsers.electrochem.html), [galvani](https://github.com/echemdata/galvani). The cited yadg interface page explicitly documents version-dependent behavior, NaN/Inf handling and unresolved metadata details; test a selected version on real exports.

## Method references that change the design

1. Dubarry and Anseán, *Best practices for incremental capacity analysis* (2022), [DOI](https://doi.org/10.3389/fenrg.2022.1023555). ICA is chemistry-dependent, and rate, noise and sampling affect interpretation. The [2023 corrigendum](https://doi.org/10.3389/fenrg.2023.1203569) corrects a duplicated Figure 13; use the updated figure. This motivates a preprocessing-sensitivity tool, not only one derivative curve.
2. Kang and Chueh, *Galvanostatic Intermittent Titration Technique Reinvented: Part I. A Critical Review* (2021), [DOI](https://doi.org/10.1149/1945-7111/ac3940). Reaction overpotentials, geometry, early transients and area uncertainty can distort diffusivity inference. This motivates explicit assumption checks before reporting D.
3. BioLogic, *Application Note 70: Determination of the diffusion coefficient ... with EIS, PITT and GITT*, [note](https://www.biologic.net/documents/determination-diffusion-coefficient-inserted-species-host-electrode-eis-pitt-gitt-techniques-an70/). Method applicability depends on the transport regime; PITT and GITT are separate branches.
4. *How to parameterise an equivalent-circuit empirical battery model from time-domain data*, [primary MethodsX article](https://pmc.ncbi.nlm.nih.gov/articles/PMC13049963/). It distinguishes experimental conditions, model structure and practical identifiability. Our adapter should therefore keep model choice and independent validation explicit.

## A reviewable action, not an opaque answer

Each proposal carries a tool name, data selection, visible parameters and a short purpose. The researcher can execute it, change parameters or send a different instruction. The accepted action runs in a browser worker so numerical fitting does not block the conversation. Its actual numerical output appears inline; raw JSON remains inspectable. The next model response must contain a concise intermediate assessment grounded in that output before recommending another action. This is a user-facing evidence summary, not a display of private model chain-of-thought.

Automatic execution is an explicit per-round option. Stop cancels the pending model request or terminates the numerical worker. Failed calls remain failures; the interface must not substitute prerecorded success. Context includes user feedback and previous numerical results. Each completed round ends with conclusions and proposed work; the researcher decides when to start another round.

## Concrete initial demonstration and expected branches

Start: compare 25C05 diagnostic indices 1 and 138, with no prediction. The agent inspects available records, proposes the selected EIS fit, waits for confirmation, shows fit metrics, summarizes them, and proposes the next relevant spectrum. Change the proposed index in the inline selector and verify the executed tool and returned output use the edited value. Alternatively send an instruction to change direction; the previous proposal becomes inactive and the next plan uses that feedback.

Numerical reference: index 1 has linear-KK RMS approximately 0.2104% and CPE weighted RMS 2.8877%; index 138 has approximately 0.1716% and 3.2373%. The opposing directions are deliberate: a correct assessment must not say improved KK consistency implies improved circuit fitting. It must not claim a unique physical degradation mechanism. Condition-matched repeats or metadata checks are appropriate next evidence.

If the researcher requests GITT diffusivity from these EIS records alone, the agent must identify missing pulse/relaxation and geometry inputs and explain that the GITT tool is not connected. If asked for capacity prediction, use the separate supported model path and preserve the negative result versus persistence. If a request needs an unavailable spectrum, show the failure and permit correction.

## Simulation tools and their different roles

The live `simulate_pulse` action evaluates the analytic one-RC Thevenin pulse/rest response. The researcher can edit OCV, current, R0, R1, time constant and pulse duration before execution. Its output includes voltage at each time, the instantaneous ohmic drop, polarization at pulse end and relaxation. The model assumes constant OCV with no SOC/thermal/degradation dynamics. Default values are illustrative assumptions, not parameters identified from the measured EIS; CPE parameters are not silently converted into an RC time constant. This provides an executable simulation action while the Python model services are developed.

PyBaMM is the intended electrochemical simulation adapter, with model complexity selected according to the question and evidence (for example SPM, SPMe or DFN). Required adapter inputs include chemistry-specific parameter-set identity/version, initial SOC/state, experimental current/voltage controls, temperature/thermal boundary conditions and solver settings. Outputs should include predicted terminal voltage and chosen internal variables, with solver status and provenance. Start with an independently checked short pulse/CC protocol before introducing degradation. PyBaMM is not currently executable from this chat.

PyBOP serves a different action: fitting or inference for selected model parameters. It requires a simulation model plus measured target signals, parameter bounds/priors, a defined objective and separate validation data. Repeated starting points, parameter sensitivity and alternative solutions belong in the result. It should not be called solely because a simulation ran, and it is not currently executable from this chat.

## Implementation status and next integration order

**Executable now:** connected public inventory; CPE numerical fit in a browser worker; existing RC/CPE and KK reference results; grouped future-capacity prediction and baselines; analytic one-RC pulse/rest forward simulation with editable parameters. The chat now accepts researcher-selected local EIS or constant-current cycling CSVs, with explicit consent before inventory/computed summaries are sent to the model. Raw CSV rows remain in the browser. This bounded adapter is not a universal vendor-native parser or full cellpy ICA/DVA integration.

**Researched, not executed by this chat:** vendor-native readers, DRT, pulse resistance, GITT/PITT diffusion models, full ICA/DVA/DMA workflows and PyBaMM/PyBOP. The first follow-on adapter should depend on the actual Argonne export available: CC cycling → local-CSV/ICA; timed pulses → pulse resistance; genuine GITT/PITT → protocol-specific transport analysis. No package is installed or called merely to decorate the demo.

Before promoting any adapter: verify its license and pinned version, compare against an independent calculation on suitable data, define rejected inputs and test researcher edits, failure recovery and source/result provenance. Scientific usefulness requires expert review and comparison with a fixed workflow, beyond successful software execution.


## 29 October update: executable research case and local-data intake

The new `compare_eis_hypotheses` action compares unchanged early parameters, an analytic R0-only adjustment and a full five-parameter refit on the same later-spectrum points/weights. The public 25C05 index1→275 case returns33.3136%,26.7035% and6.2455% weighted RMS respectively. These are descriptive in-sample residuals; added flexibility can improve a fit and does not identify a unique mechanism. The plain-language account is in [agent-story.md](agent-story.md).

Local CSV intake accepts explicit EIS or cycling columns, at most2MB/25,000rows/100cell-index groups. It rejects duplicate EIS frequencies and malformed/missing numeric values. Local EIS has no assumed KK reference or capacity labels; cross-spectrum comparison requires equal frequency grids. The `analyze_dqdv` action checks current/voltage continuity before20mV local-linear differentiation, returning derivative extrema and a bounded curve summary. These extrema are not assigned transition or degradation identities.

Selecting a new file starts a separate data context. Previous conclusions from a different file are not fed into the new task. No raw CSV rows are sent to the model or committed to the public site; explicit product consent gates inventory and derived-output transmission. This is an implemented adapter, not a claim that Lu's historical Argonne raw files have been obtained.
